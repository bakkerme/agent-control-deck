# Embedded Agent SDK: edge cases and reproduction plan

This is a risk-based inventory for the task-oriented embedded chat experiment, reviewed against experimental base `fbc5bfd5e3d13406642774ad0c8e08629e04d1a9`, SDK **0.3.302**, and the requested OpenRouter route `deepseek/deepseek-v4.1-flash-1017`. It is a finite test foundation, not a claim to cover every possible state. A deterministic fixture verifies Deck behavior under an injected schedule; it does not establish that a provider emits that schedule or implements a tool correctly.

## Evidence and execution rules

- **D**: deterministic backend test through real `EmbeddedChats`, real SQLite, and a synthetic `AgentRunner`. **B**: headless browser renderer with the workspace runtime. **L**: explicitly authorized live SDK/provider execution. **N**: native Electron window, preload, OS process or packaged-app verification. Combining letters means each layer answers a different question.
- **Existing** means an assertion exists in the named source; it does not claim a fresh successful run. **Pending** means the exact schedule is not automated. **Foundation passed** refers only to the exact deterministic slice recorded below in `tests/embedded-faults.test.ts`, using `tests/embedded-fault-harness.ts`; other schedules in the row remain pending. **Gap** means the implementation lacks a stated protection or the expected policy needs a product decision.
- **P0** protects effects, identity and durable data; **P1** protects lifecycle, availability and trust boundaries; **P2** protects presentation and less common compatibility paths. Priority is test order, not a security severity claim.
- Every synthetic test uses a new temporary database, task IDs and disposable working directory. Close queries/services/store, stop tracked children, release all barriers in `finally`, and remove the directory. Matrix cleanup codes: **C** = this standard cleanup; **K** = additionally kill/wait for the exact test child/process group, never unrelated processes; **R** = also remove a disposable renderer profile; **F** = restore injected failure hooks before service shutdown.
- Do not use arbitrary sleeps to establish ordering. Barrier names below identify observable boundaries, not production event names: `accepted`, `permissionPublished`, `effectCommitted`, `messageReceived`, `writeCommitted`, `terminal`, `ackDelivered`. Await those boundaries; use a bounded timeout solely to fail a stuck test. Keep malformed messages and transport faults labeled test-only.
- Compare actual durable rows, originating chat/task/session identity, and an independent effect ledger. A fake runner announcing “tool ran” is not evidence of a filesystem effect. Negative controls should make a test fail when replay or identity protection is deliberately disabled in the test adapter; do not ship disabled production safeguards.

## State and ownership model

A task links to one or more Deck chat IDs through `plan_chats`. Each embedded chat has a separate SDK session ID, cwd and configuration fingerprint. Folder equality does not establish ownership. A turn exists in the backend run map, independently of which task or chat the renderer currently selects.

A new send validates configuration and capacity, registers a run, and atomically records its send ID, prompt digest, user event and running state. SDK startup, session-ID receipt, transcript updates and terminal state are later boundaries. A permission request changes the presentation state to waiting; several waiters can coexist. Each decision must address the exact app request ID in the current run. Cancellation aborts the run and denies outstanding requests. A successful result ends a turn; iterator EOF without result is an error. Restart discards in-memory approvals and labels previously running/waiting turns interrupted, preserving history. There is no queued-turn product contract: another send during an active turn is rejected.

The send ledger prevents a repeated app send ID from resubmitting a turn. It does not establish exactly-once external effects, provider acceptance, or delivery of a result. A crash after acceptance but before SDK dispatch can leave a recorded send that was never executed. A crash after an effect can leave a result unknown. Neither condition authorizes silently replaying the prompt. Recovery must retain the uncertainty and require an explicit follow-up or effect-level reconciliation.

## Live admission and release gate

The initial inventory task authorized no paid calls. The cloud follow-up also dispatched none: its coordinator now blocks live acceptance pending separate budget-owner admission after containment review. Earlier live experiment evidence reported nine scenarios and seven injected faults; it is historical evidence, not this suite, and must not be promoted to coverage of the schedules above. Sanitized assertions must be reviewed before import; do not commit credentials, actual session IDs, transcripts, runtime policy or private links. A prior usage snapshot is not a current remaining-budget calculation.

A single parent budget coordinator owns the **US$20 shared total**, including earlier work. Before any live test, obtain explicit coordinator authorization for the selected case IDs and a maximum incremental spend. Do not independently inspect credentials, alter runtime secrets, or treat available credit as approval. Runtime secret injection remains backend-only.

Every authorized live run must have all of these admission controls implemented and reviewed before dispatch:

1. Explicit opt-in and coordinator reservation; fail closed without either. Check remaining shared budget using approved accounting, allow for reporting lag and reserve headroom.
2. Maximum requests, SDK turns, output tokens, wall time, total run budget and SDK/transport retry count. Verify controls exist in the installed SDK/runtime; a local abort or SDK USD limit is not a provider-side billing guarantee.
3. One synthetic disposable workspace; allowlisted tools only; independent ledger for effect cases; isolated SDK/session data; tracked child PIDs and unconditional cleanup.
4. No automatic prompt retry, provider fallback or replay after timeout, billing error, lost acknowledgement or uncertain tool outcome. Retries require a new approved case with known effect disposition.
5. Record requested/observed model route, pinned SDK version, scenario ID, assertion outcomes, duration, request/token/usage counters and provider-accounting delta when available. Report estimates separately, account for lag and never print credentials or raw transcripts.

The existing `scripts/smoke-embedded-sdk.mjs` is a limited opt-in probe; its successful initialization is not live inference, and its two-turn text/resume smoke is not an implementation of this full admission policy. Do not run it merely because the command is present.

A future native/provider release gate should observe actual raw SDK shapes with sanitized capture, then verify text streaming, exact task isolation, Read allow, Write deny with no file, question/answer, midstream cancellation, duplicate submission and restart/resume on the selected SDK/model route. Unsupported tool/question behavior is a failed or unsupported live gate, never a synthetic pass. Full native-window claims require an actual display and target OS; headless browser success remains labeled browser success.

Keep the matrix status conservative until those results exist.
